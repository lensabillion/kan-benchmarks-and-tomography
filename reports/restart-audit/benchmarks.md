# Benchmark Implementation and Experimental Audit

Audit date: 2026-09-21. Source baseline: `5fc5a05`. Cells below are **zero-based JSON cell indices**, source lines are **one-based within cell**. All 16 notebooks in both benchmark folders (including 2 vendored notebooks and 2 tutorial copies) were parsed; selected definitions were executed without training, network access, or checkpoint loading. The review followed tbd engineering and Python guidelines; experimental source files were not changed.

Reproducible bounded checks are in [benchmark_probes.py](probes/benchmark_probes.py), with [recorded outputs](probes/benchmark-results.txt). The [verification record](verification.md) identifies environments, command lines and limitations. The checks import reviewed model definitions and perform forward/backward calculations; they do not train models or load checkpoints.

## Assessment

There are useful exploratory observations, but no validated architecture-superiority, architectural equivalence, causal refinement, or symbolic-recovery result in these folders. The strongest initial work is **an implementation and protocol repair**, followed by a small architecture×optimizer×grid ablation on a preregistered target panel. The flower KAN comparisons are materially compromised by a gradient bug; the spline-MLP comparisons mix custom, vendored, and modern pykan implementations and inconsistent parameter counts. Their strongest prose often exceeds the scope of their own saved evidence.

## Findings and acceptance criteria

### B01 — P1, certain: BOTH NumPy KANs average gradients twice

[KAN vs MLP /MLP_vs_KAN_Research_Demo.ipynb](https://github.com/lensabillion/kan-benchmarks-and-tomography/blob/5fc5a0524298b0f6904e5d8b461106d552356c85/KAN%20vs%20MLP%20/MLP_vs_KAN_Research_Demo.ipynb) cell 11 L176 computes `dZ2=(A2-Y)/m`; the same cell's `KANLayer.backward` L112/L115 divide coefficient and scale gradients by m again. [KAN_vs_NN_Planar_Classification (1).ipynb](https://github.com/lensabillion/kan-benchmarks-and-tomography/blob/5fc5a0524298b0f6904e5d8b461106d552356c85/KAN%20vs%20MLP%20/KAN_vs_NN_Planar_Classification%20%281%29.ipynb) cell 21 L36 and cell 19 L19/L23 do the same. Both MLP implementations average once. Therefore every KAN parameter gradient is 1/m times the correct mean BCE gradient (not 1/m per network layer, because the propagated input derivative is not divided again). On m=400 samples lr 2 effectively becomes lr 0.005 relative to the intended mean-loss update.

Impact: invalidates causal explanations that the KAN inherently learns more slowly because splines start flat, as well as all practical MLP-vs-KAN claims made from these implementations. It does not prove that fixing the bug will make KAN win. Saved probe: numerical/implemented gradient ratio **3.9999998337513714** on 4 samples.

Fix: choose a single reduction convention. Prefer dZ=(A-Y)/m with no subsequent mean in parameter-gradient contractions; return input derivatives consistently. Acceptance: finite-difference all coefficient/scale blocks, two layers, several batch sizes; duplicating each example must leave mean-loss parameter gradients unchanged. Compare to an independent autograd implementation. Train only after checks pass.

### B02 — P1, certain: clipped spline forward and hand-coded derivative disagree

Research_Demo cell 11 L26 clips x to `[knots[d],knots[-d-1]]`; L47–56 returns derivative with respect to the clipped coordinate but omits derivative of clip. Planar notebook cell 13 L25, L55–63 repeats this. For x outside the interval, the implemented forward is constant with respect to x, so input derivative must be zero. Saved probe: max reported derivative **0.625**, finite difference **0** at x=3 with base range [-2,2]. This particularly affects backpropagation through the hidden layer's fixed [-2,2] interval.

The Cox–de Boor values themselves agree with SciPy to **2.22e-16** on the tested interior, and their partition-of-unity error is **2.22e-16**. Do not incorrectly diagnose the entire recurrence as wrong. The defect is in clipping's chain rule. Parameter gradients of the clipped spline remain meaningful; input gradients used for earlier layers are wrong outside support.

Fix: either explicitly implement saturating extension and multiply dB by the interior mask, or use an unclipped extended-knot spline and validate its intended extrapolation. Acceptance: finite differences interior, near knots, outside both ends; record fraction of each layer's activations outside its base and extended ranges throughout training. Avoid testing nondifferentiable boundary points as if they have a unique derivative.

### B03 — P1, certain: custom grid updates change the function without coefficient transport

[Example_1_function_fitting_MLP + BSpline.ipynb](https://github.com/lensabillion/kan-benchmarks-and-tomography/blob/5fc5a0524298b0f6904e5d8b461106d552356c85/KAN%20vs%20BSpline_MLP/Example_1_function_fitting_MLP%20%2B%20BSpline.ipynb) cell 2 L17–33 overwrites `grid` with adaptive knots but keeps coefficients. `fit` L105–107 calls this routine each fit stage. [Example_1_MLP_Version.ipynb](https://github.com/lensabillion/kan-benchmarks-and-tomography/blob/5fc5a0524298b0f6904e5d8b461106d552356c85/KAN%20vs%20BSpline_MLP/Example_1_MLP_Version.ipynb) cell 4 L17–33 and cell 5 L70–72 have the same structure (that version starts coefficients at zero).

Changing the basis with identical coefficients generally changes the represented function. The separate `refine` method does fit coefficients to old outputs, but the immediate next `fit` calls an unpreserved grid update. Even where repeated identical knots make the second update harmless, transport is not an invariant of this implementation. Saved deterministic probe: maximum forward difference **0.10763860006766168** after an update on 100 fixed preactivation samples. This is not an optimization step.

Fix: evaluate old curves before replacing the knots and refit coefficients, preserving old outputs to a stated numerical tolerance; reset optimizer history after reparameterization. Acceptance: test forward error before/after updates for random, constant, clustered and nonuniform inputs; detect rank-deficient least squares; measure residual transport error, not just absence of exceptions. Distinguish exact knot insertion from approximate refitting.

`src/models/kanbefair.py` constructor does not forward seed; `src/models/kan/KAN.py` L81 defaults seed 0 and L126–128 resets Torch, NumPy, Python RNG globally. ### B06 — P1, certain: test-set tuning and unequal search budgets

Example 1 factor-decomposition notebook cell 10 L8–17 and cell 26 L9–20 return best **test** RMSE over iterations; lower envelopes then select configurations. Legendre cell 19 L40–59 and cell 30 L14–26 do the same; unified sweep has 8 KAN/8 BSpline/12 plain MLP configs, different sizes, and no validation split. These are best observed test-set fits, not unbiased held-out generalization estimates. Repeating a published protocol's test peeking does not make it scientifically valid.

Feynman cell 9 correctly picks checkpoints by validation and computes RMSE as sqrt(total SSE/number of target elements). However, it logs test every epoch and later uses test lower envelopes to identify architectures/widths. Initial fixed-config checkpoint selection is better controlled; later best-across-config conclusions are exploratory. Best-of-many configurations and best-of-many seeds must not be conflated with expected performance.

Fix: frozen train/validation/test splits; all hyperparameters/checkpoints selected using validation only; one test evaluation per chosen model/seed. Equal tuning budgets and symmetric optimizer access. Acceptance: swapping/permuting test labels cannot change any selected config/checkpoint; report all attempted configs, failures, and selection rule.

### B07 — P1, certain: optimizer/refinement “factor decomposition” does not isolate those factors

Example 1 factor-decomposition compares 500 Adam full-batch steps to 200 LBFGS outer steps with up to 20 inner iterations and variable line-search evaluations, plus multiple 200-step grid stages for refined KAN. The KAN is modern pykan while BSpline is vendored and its refinement implementations are custom; fixed/adaptive grid schedules and tolerances differ. A refined small KAN result and the minimum of an independently initialized larger-model sweep do not isolate a causal refinement effect.

Feynman cell 24 L3–17 uses 25 Adam epochs over 80,000 samples versus 50 LBFGS outer steps over a fixed 5,000-point subset. L81–83 **skips plain MLP LBFGS** because “we already know it loses.” Its anchor widths 8/32/256 and grid 10/20 differ across families. This cannot establish LBFGS dominance across architectures or a fair MLP baseline.

Deep custom spline notebook cell 8 max_iter 4 / history 10 / tolerance 1e-32; pykan fit uses its custom LBFGS implementation. Same outer steps is not the same optimizer work. Fixed spline support [-4,4], clamping, absence of residual, initial pruning/regularization on KAN, and trainable parameter conventions are additional differences.

Fix: distinguish (a) controlled mechanistic ablation with one change per contrast from (b) each family's best tuned performance under equal overall search/compute budget. Log closure count, gradient evaluations, samples processed, grid-change count, wall time, memory, precision and hardware. Acceptance: paired optimizer runs use same train set; every family gets Adam and LBFGS; checkpoint and stopping rules are declared.

## Mathematical assessment for thesis/report

Representation, approximation, finite-sample generalization, nonconvex optimization, and interpretability are separate questions. Classical Kolmogorov–Arnold representation permits continuous univariate components that need not be smooth or learnable efficiently. Original KAN paper's G^(−k−1+m) theorem assumes an existing smooth compositional representation with C^(k+1) edge functions and a representation-dependent constant. It is an existence approximation bound, not a guarantee that Adam/LBFGS recovers the coefficients, not a uniform dimension-independent learning result for arbitrary data, and not an expressivity ordering against every MLP.

For the thesis proposition (PDF pp. 14–18), write definitions explicitly:
- Single-layer KAN output: y_j=Σ_i φ_ji(x_i).
- One-hidden-layer spline MLP: y_j=Σ_r A_jr ψ_r(w_r^T x+b_r)+c_j.

Every scalar single-layer KAN is additive in raw coordinates, hence rectangular mixed difference Δf=f(1,1)−f(1,0)−f(0,1)+f(0,0)=0. A spline MLP with one hidden feature z=x1+x2 and ψ(z)=z² gives f=(x1+x2)² on [0,1]^2, whose Δf=2. Cubic spline spaces contain quadratics on a properly covered interval [0,2]; this is a fixed-grid counterexample, not an appeal to arbitrary nonlinear activations. Thus the claimed same-depth function-class equality is false. Any uniform additive approximation with error≤ε at these four corners needs 4ε≥2, so ε≥1/2; this also excludes arbitrarily accurate approximation by the single additive layer. Increasing the width/output multiplicity of that single additive layer and linearly recombining remains additive.

A valid one-way construction embeds a finite single-layer spline KAN in a neuron-specific spline MLP with one hidden unit per input/output edge, W selecting raw coordinates and sparse A routing to outputs. This increases width/parameter sharing and assumes matching domains/knot spaces and zero residual or compatible residual features. The reverse can be represented by **two** KAN layers: first computes affine projections via affine spline edges, second applies ψ to those projected coordinates and sums weighted outputs. This requires depth and coverage of each projection's range. Replacing x byWx inside the “KAN edge” silently changes the model to a generalized/hybrid architecture and cannot prove the original proposition. If empirical activations are shared while theorem permits one ψ_r per neuron, the theory/experiment objects differ again. Neither construction implies equal parameter/compute cost or equal training geometry.

The exp(sin(πx)+y²) tutorial aligns almost exactly with a width[2,1,1] compositional prior. A depth/placement benefit here is plausible but expected; establishing a novel boundary needs rotations, alternative compositional targets, and controls. The target is deterministic, so “memorizes training noise” is incorrect unless measurement noise was deliberately added. A gap between train/test can still occur without label noise.

## Primary literature checked (actual URLs, dates, claims and limits)

1. Liu et al., **KAN: Kolmogorov–Arnold Networks**, 2024 preprint/revised 2025, https://arxiv.org/html/2404.19756v5 . Sec. 2.1 warns about nonsmooth classical components; Sec. 2.3 theorem assumes smooth edges. Residual SiLU and adaptive grids are integral implementation details. Useful motivation, not universal optimization superiority. Official implementation https://github.com/KindXiaoming/pykan explicitly describes science focus, small-scale examples and need for tuning.
2. Yu, Yu, Wang, **KAN or MLP: A Fairer Comparison**, 2024, https://arxiv.org/html/2407.16674v2 and official https://github.com/yu-rp/KANbeFair . Controls parameter/FLOP axes, experiments spline activations before/after linear maps, reports spline MLP parity/improvement on its symbolic tasks. Sec. 5 reports best test metrics over epochs/envelopes; not a gold-standard held-out statistical protocol. Thus local rerun should improve the protocol rather than inherit all limitations. Higher-dimensional explanation is not supported by its local loader.
3. Liu et al., **KAN 2.0: Kolmogorov–Arnold Networks Meet Science**, 2024, https://arxiv.org/abs/2408.10205 . Introduces MultKAN multiplication nodes, kanpiler, tree conversion and structured discovery workflow. It is a different architecture/workflow version, not evidence that plots from a vanilla spline regressor equal symbolic discovery.
4. Shukla et al., **A comprehensive and FAIR comparison between MLP and KAN representations for differential equations and operator networks**, 2024, https://arxiv.org/abs/2406.02917 . Reports accuracy/efficiency weaknesses for original B-spline KANs and improved low-order polynomial variants, seed/degree robustness concerns. Relevant motivation to log failure rates and computational cost; task class is PDE/operator learning, not these regressions. FAIR here is also data/software principles, not proof of every resource-matching decision.
5. Poeta et al., **A Benchmarking Study of Kolmogorov-Arnold Networks on Tabular Data**, 2024, https://arxiv.org/abs/2406.14529 ; official https://github.com/eleonorapoeta/benchmarking-KAN . Reports comparable/better classification accuracy/F1 with higher training cost under its setup, contrasting with Yu's broader task suite. This illustrates dependence on protocol/task, not evidence to select whichever conclusion is preferred.
6. Kratsios, Kim, Furuya, **Approximation Rates in Besov Norms and Sample-Complexity of Kolmogorov-Arnold Networks with Residual Connections**, 2025 v3, https://arxiv.org/abs/2504.15110 . Verified latest title differs from earlier search-index title “Approximation and Learning Guarantees for Functions and their Derivatives.” Gives approximation and pseudodimension/sample guarantees for specified residual models/regularity/noiseless sampling; not direct Adam/LBFGS convergence claim for current notebooks.
7. Bagrow, Bongard, **Optimized Architectures for Kolmogorov-Arnold Networks**, 2025 preprint revised 2026-04-20 v2, https://arxiv.org/abs/2512.12448 . Uses sparsification, deep supervision, depth selection and MDL objectives. Reports sparsification alone insufficient. Relevant recent adjacent work; not independently replicated by this audit and not direct proof of superiority.
8. Southworth et al., 2026 **Multilevel Training for Kolmogorov Arnold Networks**, https://arxiv.org/html/2603.04827v1 . The full text was checked in the integrated review. It connects spline KANs to multichannel power-ReLU networks by a change of basis and examines their optimization geometry. Do not conflate a valid basis transformation to a multichannel network with the false same-depth spline-MLP theorem above.

## Recommended first experiment / restart contract

**Gate 0: correctness before long training.** Build one small importable harness in a pinned environment; retain notebook demos as views. Carry probes B01–B05 as meaningful regression checks, add RMSE aggregation, shape equality (pred.shape==target.shape), finite values, split-disjointness, test-independence and grid-transport checks. Save active parameter counts and gradient-connected flags. Do not suppress NaNs into apparently finite predictions. Explicitly label numeric precision; use float64 for initial numerical diagnosis and a planned float32 comparison.

**Initial panel:** (i) additive `sin(πx)+y²`, (ii) compositional `exp(sin(πx)+y²)`, (iii) ridge interaction `(x+y)²` or `sin(π(x+y))`, (iv) rotated compositional target `f(Qx)` with fixed orthogonal Q, (v) the current 4D nested target. Domain and output normalization fixed from training/known analytic scales. Rotation must ensure same sampled-domain interpretation; sample u uniformly on original domain and map x=Qᵀu for one paired experiment, or explicitly acknowledge changed distribution if sampling x in unchanged cube.
